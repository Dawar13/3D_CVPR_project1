# E3 — Can bad hints be caught at test time, using only the photos? (method evaluation)

Frozen at tag `e3-prereg` (2026-11-08) before any E3 eval run, after the user's go-ahead ("do everything to make this paper as strong as possible ... our methods and solutions but it has to be solid").

## 1. The method (E3, unchanged since `e2x-prereg`; `exp1/e3.py`, `exp1/witness.py`)
- **Witness:** the model's own photos-only predictions under several view orders. It gives each camera's relative rotation and its uncertainty, with no ground truth.
- **Error model:** the hint rotations vs the witness are fitted as a world-shared offset (heading), a camera-mount offset, a drift along the view order, and per-camera residuals.
- **Rule:**
  - a group part is repaired if it exceeds z · hypot(σ, floor);
  - a single camera's pose hint is dropped if its residual exceeds z · hypot(σ_view, floor);
  - depth hints are rescaled (shared scale off by more than τ_shared in log) or dropped per view (τ_view), using depth measured in the units of the pose hints.
- **Then:** the model is run again with the repaired hints. `witness` = repair (the method); `witness_drop` = drop instead of repair (ablation).

## 2. Thresholds (frozen; `configs/e3_eval_*_mapanything.json`, generated by `scripts/e2x/make_e3_eval_configs.py`)

| Setting | Value | Source |
|---|---|---|
| e3_z | **5.0** | **Secondary** calibration (E2X E3-cal amendment 1, tag `e3cal-amend1`): ETH3D dev + TUM fr3, accurate ground truth, 22 clips, 50 decisions, 0% false actions at z = 5 (12% at z = 4). The **primary** calibration (SceneFun3D) was NOT CALIBRATED for the pose part (13.8% at z = 5) and is reported first. |
| e3_tau_depth_shared | 0.20 | primary calibration (3.6% false rescales on 110 GT depth decisions) |
| e3_tau_depth_view | 0.25 | primary calibration (1.9% false drops) |

Caveat, stated in advance:
- 0 false actions in 22 clips is compatible with a true rate of up to about 13% (95%).
- z = 5 is the most conservative grid value, so E3 can only act on large or clearly measured errors.

## 5. Tests (`scripts/e2x/analyse_e3.py`; one Holm family over all primary tests; α = 0.05; practical thresholds of E2: shape 1 pp, rotation 0.25°, real size 5 pp; scene means, paired over scenes)
- **SAFE** (on correct hints): Δ = E[E3] − E[as given].
  - Conditions: `clean_pose`, `clean_pose_depth2` (ETH3D); `gt_pose`, `gt_all`, `dev_pose`, `dev_all` (real clips; iPad hints that help, E2-E and X-B).
  - Metrics: shape, rotation (+ real size on real clips).
  - A test is harmful if it is Holm-clear and Δ ≥ threshold. **E3 is SAFE if no test is harmful.**
- **HELP** (on bad hints): Δ = E[E3] − E[as given]; helpful if Holm-clear and Δ ≤ −threshold.
  - Rotation: one camera 15/30/90°, 20/40% of cameras wrong, shared heading 5/10°, mount 5° (`c6_shared_rot`), drift 2/3.
  - Shape: depth scale 0.67 / 1.5, one depth view ×1.5, and on real clips `ai_depth` and `dev_pose_ai_depth`.
- **BEST** (vs the best existing remedy): Δ = E[E3] − E[best of R0/R2/R3]. "Best" is chosen per condition on these same data, in the baselines' favour. Better if Holm-clear and Δ ≤ −threshold.

## 6. Decision (fixed now)
- **The E3 method claim holds** if:
  - E3 is SAFE, **and**
  - HELP and BEST both hold on at least one *agreeing-error* condition (shared heading, mount, drift) or one real AI-depth condition.

  These are the cases where per-camera filters and model confidence are blind (E2-C P10/P11, E2-F).
- **Otherwise** E3 is reported as a negative or limited result, together with exactly which part failed.
- **Descriptive only:**
  - safety vs benefit (`e3_safety_benefit.csv`: share of the good-hint benefit kept, share of the bad-hint damage removed, per remedy);
  - the E3-drop ablation, ORACLE, runtime and extra passes.

## 7. Run (`scripts/session_queue_e3.sh`, from the session-A tree = the calibration's frozen experiment code)
- **Dev gate:** 0 failures on ETH3D dev c0 and room dev clips. Out-of-memory failures are reset and rerun with identical code (`scripts/e2x/retry_oom.py`).
- **Then:** ETH3D eval, room eval and E2-E eval, each once.
