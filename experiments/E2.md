## 0. Ground rules

### 0.1 Research practice
1. **Preregister every eval run.** Write the grid, metrics and the question each test answers in this file's §8 (Preregistration log). Debug on dev scenes only, then commit and tag `e2-prereg-<part>` before the eval run.
2. **Primary metrics are fixed in advance** (§0.2). Everything else is labelled exploratory.
3. **Multiple comparisons.** With many tests, some will look significant by luck. Apply the Holm–Bonferroni correction across all preregistered primary tests in a part, and report both raw and corrected results.
4. **Two thresholds for "it matters":** a result must be statistically clear (paired 95% CI excludes 0 after correction) **and** large enough to matter (§0.2). A 0.05° change is not a finding, even if it is significant.
5. **Statistics unit.** Use the scene as the unit; when there are several clips per scene, bootstrap over scenes.
6. **Honesty.** Every number in a report comes from a results file, and every citation was opened by you. Report tests that show nothing as clearly as tests that show something.

### 0.2 Metrics (fixed for all of E2)

| Name | Plain meaning | Practical threshold ("matters") |
|---|---|---|
| Shape error | Average 3D point error after one overall size correction, as % of distance | ≥ 1 percentage point change |
| Real-size error | Same, without the size correction (real meters) | ≥ 5 percentage point change |
| Rotation error | How wrong the camera directions are, in degrees (pairwise) | ≥ 0.25° change |
| Scale ratio | Predicted scene size ÷ true size | ≥ 5% off |
| Absorption | Fraction of the injected error that appears in the model's output (0 = ignored, 1 = copied) | descriptive |
| Confidence AUROC | How well the model's own confidence ranks bad views below good ones (0.5 = guessing) | descriptive |

### 0.3 Sharing the A100 safely
- Before every run, check `nvidia-smi`. Only start if at least 20 GB are free. MapAnything peaked at 8.26 GB in E0; check OmniVGGT in §4.1.
- In each run script, call `torch.cuda.set_per_process_memory_fraction(0.25)` on the 80 GB card, and set `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True`.
- Run jobs in `tmux`, one at a time, resumable (the E1 runner already resumes). Never kill or touch the other project's processes.
- Log the start/end time and the peak memory of every job to `results/e2_*/gpu_log.txt`. Timings while sharing will be slower than E0's 0.26 s per inference; record the real numbers.

## 3. E2-C: how the problem behaves (MapAnything, ETH3D) [CC writes, YOU run]

**Data:** the same 13 ETH3D scenes. Add **2 more non-overlapping 10-photo clips per scene** where possible (3 per scene), to measure across more situations. Dev = the 3 dev scenes; eval = the 10 eval scenes. Use 3 seeds for random directions.

Each test answers one question. Write the question, the conditions and the primary metric into §8 before the eval run.

**C1: The trust curve. How strongly does the model follow a hint, as the hint gets more wrong?**
- One camera's rotation wrong by 1, 2, 5, 10, 15, 30, 60, 90 and 180°.
- One camera's position wrong by 0.05, 0.1, 0.25, 0.5, 1, 3 and 10 L.
- All distances × 0.5–2 (7 steps).
- Depth on 2 views × 0.5–2 (7 steps).
- Focal length on all views × 0.7–1.3 (7 steps).
- **Measure:** absorption and confidence at each step.
- **What it tells us:** whether the model ever stops trusting a hint once it becomes obviously wrong (an "override point"), or copies it at any size. A blind copier and a partial truster need different fixes.

**C2: Does it know but still obey?**
- For every corrupted view in C1, relate the confidence drop to absorption.
- **Measure:** the correlation between them (Spearman, across views and severities), and the confidence AUROC at each severity.
- **What it tells us:** if confidence falls while absorption stays high, the model "knows but obeys". That means the information to resist is already inside the model.

**C3: Which outputs does a wrong hint damage?**
- For the bad view in C1, measure separately:
  - its **placement** (pose error);
  - its **own shape** (depth error after fitting that view alone to the truth with one rotation, shift and scale);
  - its **lens output** (predicted focal vs true);
  - the **good views' shape and placement**.
- **What it tells us:** whether a wrong hint only puts a camera in the wrong place (a fix only needs to re-place it) or also bends the 3D shape (a fix must redo the shape).

**C4: Which hint channel causes it?**
- Corrupt one ingredient at a time, at matched sizes:
  - rotation only;
  - position *direction* only (same distance);
  - position *distance* only (same direction);
  - overall scale only;
  - depth only;
  - lens only.
- **Diagnostic only, not a fix:** also run the mean→median scale patch behind a flag, on the conditions that change scale. This tests whether the averaging step matters.
- **What it tells us:** which channel the model over-trusts. The median probe directly tests the "average scale" idea, which E1 suggested is minor.

**C5: Does the model use the photos as evidence?**
- For each corrupted view, measure how much evidence the photos give about it:
  - overlap with the other views (the share of its true 3D points visible in other photos, from ground-truth depth);
  - texture (image gradient energy).
- Relate absorption to these.
- **Also vary the number of photos:** 4, 10 and 20 views (20 only where the clip allows), with one bad camera at 15°.
- **What it tells us:** if absorption is lower when the photos give strong evidence, the model weighs evidence (rational trust). If absorption is the same regardless, it is blind trust.

**C6: Independent vs correlated errors at the same size.**
- Give every camera a rotation error of the same size (2°, 5°), in two ways:
  - (a) random directions per camera (independent);
  - (b) the same direction for all cameras (shared).
- Do the same for drift vs random jitter of matched total size.
- **Measure:** harm, confidence AUROC, a scene-level confidence summary, and the E1 simple filter's recovery.
- **What it tells us:** whether *agreement between errors* is what makes them undetectable, with the size held equal.

**C7: Partial hints.**
- Poses given for 30%, 60% and 100% of views (view 0 always), with one bad camera among the posed views.
- **What it tells us:** whether one bad hint weighs more when fewer hints are given.

**C8: What can the photos alone reveal?**
- Without any hints, measure how accurately photos alone recover:
  - relative rotations between cameras;
  - relative translation directions;
  - metric scale (scale-ratio spread);
  - per-view depth scale.
- **What it tells us:** this sets the ceiling for any future test-time fix. An error smaller than the photos' own uncertainty cannot be detected from the photos. For example, if photos alone get scale wrong by about 13%, a 1.1× scale error is invisible.

**Approximate size:** about 4,000–5,000 inferences on ETH3D. At E0's speed (0.26 s, unshared) that is roughly 20–40 min; it will be longer while sharing.

## 5. E2-E: real sensor hints [CC + YOU]

**Why:** all E1 errors were made by us. Reviewers will ask whether real sensors produce these errors and whether the harm appears with them. This is the strongest answer to "are your corruptions realistic?"

1. **Choose one dataset** from the E2-A table. It must:
   - include real hint sources (device VIO poses, device depth, device intrinsics) **and** better ground truth;
   - not be in the models' training data (or have a clearly held-out split);
   - be downloadable under a research licence in reasonable time.

   If access needs approval (e.g. ScanNet++), request it now and start with another dataset that can be downloaded immediately.
2. **Download only what is needed:** about 10–20 scenes, 3 clips each, 10 views per clip.
3. **Conditions:** images only; images + real device intrinsics; + real device poses; + real device depth; + all real hints; + the same with ground-truth hints (the ceiling).
4. **Measure:**
   - whether real hints help or hurt vs images-only, and by how much;
   - absorption of the real hint error;
   - where real errors fall on the C1 trust curves;
   - what type the real errors are: independent, drift-like, scale-like, or depth edge-bleeding. Measure this by comparing the real hints with the ground truth.

## 6. E2-F: what do existing remedies leave unsolved? (baselines, not our method) [CC writes, YOU run]

**Why:** a method paper needs to show that the problem is *not already solved* by tools that exist today. This sets how big a gain E3 has to deliver. Run on the families that matter (after E2-B) and on the real-sensor data from E2-E:

| Remedy | What it is |
|---|---|
| R0 | Images only (ignore all hints) |
| R1 | Drop all pose hints, keep lens/depth |
| R2 | E1 simple filter (disagreement with images-only) |
| R3 | Drop views the model's own confidence marks low, then rerun (threshold chosen on dev scenes) |
| R4 | Robust bundle adjustment after the network: refine poses using image feature matches with a robust loss and the hints as soft priors (e.g. pycolmap / Ceres with a Cauchy loss) |
| R5 | VPGGT, if code and weights are released (training-based robustness) |
| R6 | TCO, if code is released (test-time prior handling) |

**Measure:** for each family, the **remaining gap** = (remedy error − clean-hint error) ÷ (damaged error − clean-hint error), where 0 = fully solved and 1 = no help. Also record runtime and false alarms (good hints dropped).

- **Unit and statistics.**
  - The scene is the unit: average over seeds and clips within a scene, then over scenes.
  - 95% CIs are a bootstrap over scenes. p-values come from a two-sided t-test over scene values.
  - The Holm family is exactly the 12 primary tests below. A primary test is a **finding** only if it is Holm-clear and passes its threshold in the stated direction. Everything else is exploratory.
  - If the scene values of a test have zero spread (e.g. AUROC = 1 in every scene), the t-test is undefined; the exact sign-flip p is used instead. Both p-values are always reported.
- **Thresholds.** Error metrics use the §0.2 thresholds. Absorption (0.10), AUROC (0.15 above 0.5) and Spearman (0.30) have no §0.2 threshold; these values are set here, before any eval run.

| Test | Question | Scene value | Finding if |
|---|---|---|---|
| P1 | C1: does the model stop following a grossly wrong rotation? | absorption at 30° − absorption at 15° (one view) | ≤ −0.10 |
| P2 | C1: same for position | absorption at 10 L − at 0.25 L | ≤ −0.10 |
| P3 | C2: does its confidence flag the bad view? | within-run confidence AUROC at 15° − 0.5 | ≥ 0.15 |
| P4 | C3: does a wrong rotation bend the bad view's own shape? | Δ own-shape error of the bad view vs clean, 15° | ≥ 1 pp |
| P5 | C3: does it bend the good views' shape? | Δ mean own-shape error of the good views vs clean, 15° | ≥ 1 pp |
| P6 | C4: does the median statistic itself change clean results? | `clean_pose_median` − `clean_pose`, rotation error | \|Δ\| ≥ 0.25° (two-sided) |
| P7 | C4: does the median fix the 10 L GPS jump? | median − mean run, shape error, one view 10 L | ≤ −1 pp |
| P8 | C5: is less copied where the photos give more evidence? | per scene: Spearman(overlap, absorption minus its mean for that scene and setting), one bad camera at 5/10/15/30° pooled | ≤ −0.30 |
| P9 | C5: is less copied with more photos? | absorption with 20 photos − with 4 (view 3 at 15°) | ≤ −0.10 |
| P10 | C6: does the model notice a shared error less than independent errors of equal size? | (mean confidence shared 5° − mean confidence independent 5°) ÷ mean confidence of clean_pose | ≥ +0.10 |
| P11 | C6: does it notice drift less than matched jitter? | the same with drift level 2 vs matched jitter level 2 | ≥ +0.10 |
| P12 | C7: does one bad hint weigh more when fewer poses are given? | harm with 30% posed − harm with 100% posed (rotation, bad − clean at the same fraction) | ≥ 0.25° |

C8 (what photos alone reveal) is descriptive by design: quantiles of the images-only errors. It decides which hint errors any image-based check could see.

**Exploratory, not tested:**
- the C6 harm comparison. The pairwise rotation metric barely sees an error that all cameras share: a common camera-frame rotation cancels between non-reference cameras and shows up only in the pairs with view 0. Harm at equal per-view size is therefore not comparable across correlation structures with this metric.
- C1 trust curves at all sizes, C2 correlations, C3 placement/lens readouts, the C4 channel table on the pixel-size axis, C5 texture.
