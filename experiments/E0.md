# E0 — Setup, interface verification and smoke test

**Goal:** make sure Shubh's harness runs, matches the *real* MapAnything interface, and gives sane numbers, *before* any experiment result is trusted. E0 produces no research findings. It produces trust in the pipeline, plus measured runtime and memory.

**Time:** about 1 day. Data download may take a few hours, so start it first (Step 4) and do Steps 2–3 while it runs.
**Where:** GPU server only. One GPU with ≥ 24 GB. do al the things necessary before i rent a VM and give u the GPU 
**Output:** a filled `MapAnything_Exp1/reports/exp1_environment_and_reproduction.md`, a new `reports/e0_interface.md`, smoke results in `results/smoke/`, and a log entry in `context.md`.

Who does what:
- **[YOU]** run commands on the server.
- **[CC]** = Claude Code writes, reads or edits code.

## Step 3 — Interface verification by reading the installed source (1–2 h, no GPU) [CC]

Read `third_party/map-anything` (the installed commit). For each item, record **the answer plus file:line evidence** in a new file `reports/e0_interface.md`. Fix `exp1/model_io.py` wherever reality differs; it is the only file allowed to call MapAnything.

| # | Question | Why it matters |
|---|---|---|
| 1 | Exact signatures of `MapAnything.from_pretrained`, `preprocess_inputs`, `model.infer`, and which kwargs `infer` accepts (`memory_efficient_inference`, `use_amp`, `amp_dtype`, `apply_mask`, `mask_edges`, `apply_confidence_mask`) | Wrong kwargs crash or silently change behaviour |
| 2 | Expected `img` format: HxWx3 uint8 0–255 tensor or numpy? Is `data_norm_type` required, and who sets it? | Wrong normalisation means garbage predictions |
| 3 | Format of `intrinsics` (3×3), `camera_poses` (4×4 OpenCV cam2world, or quat+trans?) and `is_metric_scale` (shape, per view?). What is the default when a key is absent? | Pose convention errors look like "the model is bad" |
| 4 | Output keys and shapes: `pts3d`, `depth_z`, `camera_poses`, `conf`, `mask`, `metric_scaling_factor` (batch dim? trailing dims?) | `model_io.run` indexes these |
| 5 | Does anything resize the input? What size constraints apply (multiple of 14, max side 518)? Is 518×336 kept exactly? | `metrics.evaluate` requires prediction size == GT size |
| 6 | Partial poses: is "view 0 posed, some others not" accepted? Where is this validated? | Both controls depend on it |
| 7 | **Missing-hint handling inside the model:** when a view has no pose/rays/depth, is that feature term skipped, set to zeros, or replaced by a learned token? Quote the code. | Defines what "gate = 0" means in E3 and later |
| 8 | **Scale normalisation:** where are the pose scale ẑp (mean camera distance) and depth scale ẑd (mean depth) computed? Is it a mean? Over which views? Is the reference frame view 0? | This is the patch point for E2 (mean → median) |
| 9 | How is `is_metric_scale` used? Per view or global? Does it gate the scale features? | Decides whether the corruption tests the scale path at all |
| 10 | Checkpoint licence (`facebook/map-anything` = CC BY-NC 4.0; `-apache` = Apache 2.0). Record which one is used. | Paper reproducibility statement |

Also append a short section "Model internals relevant to E2/E3" to `reports/e0_interface.md`. It should name the fusion code (where the LayerNorm-sum happens) and the exact lines to patch for the median, so E2 can start immediately.

## Step 4 — Download and prepare ETH3D (1–3 h, mostly waiting) [YOU + CC]

1. From eth3d.net → High-res multi-view → **training data**, download:
   - `multi_view_training_dslr_undistorted.7z` (images + undistorted calibration)
   - `multi_view_training_dslr_depth.7z` (ground-truth depth)
   
   Note the licence: CC BY-NC-SA 4.0.
2. Unpack both into the same root, e.g. `/data/eth3d` (`7z x <file> -o/data/eth3d`).
3. **[CC] Check the layout** against what `exp1/datasets.py` expects. Run `ls` on one scene and confirm these paths exist:
   - `<root>/<scene>/images/dslr_images_undistorted/DSC_*.JPG`
   - `<root>/<scene>/dslr_calibration_undistorted/cameras.txt` and `images.txt`
   - `<root>/<scene>/ground_truth_depth/dslr_images/DSC_*.JPG` (raw float32, not real JPEGs)
   
   If anything differs, fix `datasets.py`, not the data.
4. Make the clips:
```bash
python -m exp1.datasets --eth3d_root /data/eth3d --out data/clips --n_views 10 --size 518 336
ls data/clips        # expect dev__<scene>__c0.npz (3 scenes) and eval__<scene>__c0.npz (10 scenes)
```
Each line printed should show `valid_depth` well above 0%. Note any scene that gets skipped.

## Step 5 — Ground-truth self-consistency check (30 min, CPU) [CC writes, YOU run]

This catches pose-convention bugs before the model is involved. Write `scripts/e0_check_clips.py`. For every clip:
- **Depth reprojection test.** For view pairs (0, j), take GT depth of view 0, unproject with K₀ and pose₀, then project into view j with K_j and pose_j. Compare the projected depth with view j's GT depth on overlapping valid pixels. Report the median relative depth difference and the overlap %.
- **Visual check.** Save one PNG per clip: view 0 image, its GT depth (coloured), and view 1 with reprojected view-0 points drawn on top.

**PASS:** median relative difference < 3% on every clip with meaningful overlap (> 5% of pixels).
**If it fails:** the poses are probably world2cam where cam2world was expected (or the reverse), or K was adjusted wrongly in the resize/crop. Fix `datasets.py` and regenerate the clips. Do not continue until this passes.

## Step 7 — Smoke runs on one dev clip (30 min, GPU) [YOU]

Use whichever clip landed in `dev__`:
```bash
CLIP=$(ls data/clips/dev__*.npz | head -1)
python -m exp1.run_exp1 --config configs/pilot.json --clips "$CLIP" --out results/smoke \
  --only rgb_only rgb_K clean_pose clean_pose_noK zero_noise
# exercise the corruption + both controls once (partial-pose path):
python -m exp1.run_exp1 --config configs/pilot.json --clips "$CLIP" --out results/smoke_ctrl \
  --only rgb_only clean_pose "outlier_rot_rot_deg=15"
```
**[CC]** Then read `per_run.csv`, `failures.jsonl` and `corruption_manifest.json` and check the following.

| Check | PASS if | If not |
|---|---|---|
| All rows `status=ok`, `failures.jsonl` empty | yes | read the traceback and fix `model_io.py` |
| Prediction size == 518×336 (no resize error) | yes | change `--size` to what the model keeps, regenerate clips |
| `zero_noise` vs `clean_pose`: `max_abs_diff_vs_clean_pts3d` in the manifest | tiny (bf16 noise; < 0.1% of scene size L) | investigate non-determinism |
| **Hints help:** `clean_pose` better than `rgb_only` on `pts_relerr_scale` and `rre_deg` | clearly better (the paper shows large gains) | almost always a pose convention / units / metric-flag bug. Do not proceed |
| `rgb_K` ≥ `rgb_only` on the same metrics | roughly equal or better | check the intrinsics adjustment after crop |
| Controls ran (`drop_oracle`, `filter_rgbcheck` rows exist) | yes | partial poses not accepted; redesign controls |
| Runtime and peak memory per 10-view inference | recorded | — |
